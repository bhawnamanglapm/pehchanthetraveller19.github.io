## Why it matters

0a questions 2 ("Do Indians want to go there?") and 3 ("How crowded is it with creators already?") are answered by
the traveller alone in phase 1. Real counts make the scoring less of a guess.

## What to build

| Part | Detail |
|---|---|
| **Job** | `/api/cron/creator-counts`, weekly, protected by `CRON_SECRET`. For each destination, YouTube Data API v3 search for recent travel videos (query terms set per destination in Strapi), saves count and total views |
| **Storage** | Only the counts and the date counted. Refreshed or deleted within 30 days, as YouTube requires; a weekly run keeps within that. Nothing older than 30 days is ever shown |
| **Quota** | Stay inside the free daily quota; spread destinations over the week if needed |
| **On the page** | Questions 2 and 3 are pre-filled as suggested scores, with "Counted on [date]". The traveller can still change them. Instagram stays the traveller's own check |
| **Key** | `YOUTUBE_API_KEY` in Vercel environment variables only |
| **Failure** | Email admin; the page falls back to "traveller scores this" |

The score still comes from the formula in `score0a.ts`, never from AI.

## Rules from 2.01 (checked 18 Nov 2026)

See [2.01 findings §6](../research/2.01-findings.md#6-youtube-data-api-v3).

- Free quota: 100 `search.list` calls a day, plus 10,000 units for other calls. `videos.list` and `channels.list`
  cost 1 unit each. With 100 searches a day, spread the places over the week.
- No channel owner authorises us, so **every** stored count (views and subscriber counts too) is kept no longer
  than 30 days, then refreshed or deleted (Developer Policies III.E.4.b and III.E.4.d).
- More quota needs an API Compliance Audit. Don't plan on it.

## Acceptance criteria

- [ ] A count older than 30 days is never shown or kept.
- [ ] A week's run stays inside the quota for the planned number of destinations.
- [ ] The traveller can override a suggested score.
