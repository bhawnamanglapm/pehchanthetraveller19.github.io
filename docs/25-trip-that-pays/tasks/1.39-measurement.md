## Why it matters

It shows whether the trip really pays for itself, which stage loses people, and when the stay marketplace is ready
to charge. It's also the evidence for every pitch.

## Measures

| Measure | How it's worked out | Why |
|---|---|---|
| **Main: trips that reach stage 3 with a Trip Balance** | `trip_closed` count, by net band | Proves the promise, or shows honestly that it doesn't hold |
| Commission per trip started | Monthly `commission-log` total ÷ `trip_started` that month | The first income line |
| Where travellers drop off | `stage_completed` counts by stage | Which stage to fix first |
| Hotels open to creators, per destination | Count of stays with the creator badge in Strapi | When income line 4 can charge |
| Most-skipped steps | `step_skipped` by step and reason type | Feeds the monthly routine |
| Checkpoint colour at departure | `checkpoint_status` | Whether stage 1 guidance works |
| Mode split | `mode` | How many travellers want Creator mode |

No personal data in any event. `trip_closed` sends a band, not the exact figure.

## Dashboard

One view in the chosen analytics tool, plus the commission total from Strapi. Reviewed in the monthly session.

**Where each measure is read (18 Nov 2026).** The tool is Umami Cloud on the free Hobby plan (frontend
`docs/ANALYTICS.md`). It only counts on the production site, and only once the Umami id is set (it is). Every event
carries fixed values only: a stage, a step id, a band or a mode, never anything a traveller typed.

| Measure | Where | Event and property |
|---|---|---|
| Trips closed with a Trip Balance | Umami, Events | `trip_closed`, broken down by `band` (loss, break_even, profit) |
| Commission per trip started | Strapi **Trip · Commission log** (that month's rows) ÷ Umami `trip_started` for the same month | One division, done in the monthly session |
| Drop-off by stage | Umami, Events | `stage_completed` by `stage` (0a, 0b, 1, 2, 3) |
| Hotels open to creators | Strapi **Trip · Stay**, filter `openToCreatorStays` = true, by destination | — |
| Most-skipped steps | Umami, Events | `step_skipped` by `step` and `reason` |
| Checkpoint colour | Umami, Events | `checkpoint_status` by `status` |
| Mode split | Umami, Events | `trip_started` by `mode` (and `mode` when it's changed) |

**Owner step:** in Umami, save these event reports as one view (Umami's own reports or a bookmark per filter, as
the free plan allows). Claude has no Umami login, so this step is the owner's.
