## Why it matters

The original plan reused these parts in place. Now the trip app is separate, so each part is either copied in,
replaced, or linked to. Deciding this once avoids every stage task re-asking it.

## Inventory: decide and record one of copy, replace or link for each

| Part in the existing app | Use in the trip app | Proposed |
|---|---|---|
| `/api/revalidate` route | Clear the trip app's cache when Strapi content changes | **Copy**, with its own secret (1.13) |
| Resend email helper | Admin emails (1.15), reminders (2.07), sign-in links (3.03) | **Copy** |
| Trip-plan share (`/trip-plan`) | "Share with a trusted contact" | **Copy** the share approach (1.25) |
| Offline page and "Save offline" | Stage 2 offline | **Copy** the approach (1.18) |

## Rules

- Copied code keeps a short comment at the top saying where it came from and the date, so later fixes can be
  carried both ways.
- Nothing calls the existing app at runtime unless this table says "link".

## Acceptance criteria

- [ ] Every row has a recorded decision (copy, replace or link).
- [ ] Phase 1 "copy" items are in the trip repo and pass its tests.
