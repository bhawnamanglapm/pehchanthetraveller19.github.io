## Why it matters

The main website's navigation is how most visitors will find the trip pages.

**Changed 15 Nov 2026 (owner, D2 and D7):** the trip pages live in the existing Next.js app at
`www.pehchanthetraveller.com/trip/`, and the link goes in **that app's** header, phone menu and footer. It's built
there behind the `tripApp` switch, so it appears only at launch, and clicks send `nav_trip_click` with `context` set
to `desktop`, `drawer` or `footer`. The sections below are the original plan for this static repo's nav. Adding the
same link here is optional and decided separately.

## Where the link goes (this repo)

The nav is built from one model, `navModel(g)` in [src/lib/shell.mjs](../../../src/lib/shell.mjs), used by the
masthead, the drawer and the footer.

| Place | Today | Change |
|---|---|---|
| **Desktop nav** | `navModel` returns four items (Profile, Destinations, Real Trips, Safety). `masthead()` renders each as a `<button data-mega>` that opens a mega-menu | Add a fifth item with a `direct: true` flag (or an empty `columns` list) for the trip app. `masthead()` renders a direct item as an `<a class="nav__link">` instead of a button, and the mega-menu and drawer loops skip it. The code comment already says "Five, not thirteen" |
| **Drawer (phone)** | `<details>` per nav item, then flat links: Report something, Women & Travel, Partner With Us, About | Add the trip link as the first flat link, so it's visible without opening a section |
| **Footer** | "Plan your trip" column: Solo Travel Profile, The document, Safety, Travel Tools, Search | Add the trip link to this column |

## The link itself

- Label: from D2 (proposed "Plan a trip that pays").
- `href`: `https://www.pehchanthetraveller.com/trip/` (1.02).
- Same tab (it's Pehchan's own product), so no `target="_blank"`.
- `data-track="nav_trip_click"` plus a `data-where` value (desktop, drawer, footer), using the existing
  `assets/js/analytics.js`. Check that the script's automatic outbound-link tracking doesn't count the click twice.
- Shown on every page, because the nav is shared.

## Rules

- This repo is public. Only the link goes here: no trip app code, no tokens, no admin content.
- Build and check with `src/build.mjs` as usual; the change touches only the shell.
- Optional, separately decided: add the same link to the existing Next.js app's nav. That's a change in that app's
  repo, not this one.

## Acceptance criteria

- [ ] The link appears in the desktop nav, the phone drawer and the footer on every built page.
- [ ] Keyboard: tabbing through the desktop nav reaches it in order, and it doesn't try to open a mega-menu.
- [ ] Clicking it fires `nav_trip_click` once with the right `where`.
- [ ] The link goes live only when the trip app is launched (1.40), not before.
