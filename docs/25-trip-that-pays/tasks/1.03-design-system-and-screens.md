## Why it matters

The app is separate, but to a traveller it must feel like Pehchan. One set of components keeps the five stages
consistent and lets developers build each stage without redesigning.

## Brand continuity with the main site

- Copy the main site's colour tokens, display face, body font, light and dark themes, and spacing scale from its CSS
  (`assets/css` in the main site repo). Same wordmark.
- The header: wordmark linking back to the main site, the trip name, a theme toggle, and the trip menu (1.22).
- The footer: legal links for the trip app (privacy, terms, affiliate disclosure) and a link back to the main site.

## Components to design (each with every state)

| Component | States |
|---|---|
| **Trip Card** with **Trip Balance** | Empty, filled, negative net, "expected" grey amounts, to-dos present, mode switch |
| **Stage stepper** | Current, done, not reached, going back to an earlier stage |
| **Honesty strip** | Collapsed one-liners with "why" links |
| **Block headers** | Do · Earn · Points · Stay free · Safety |
| **Step card** | Not started, in progress, done, skipped (with reason), not needed, a broken link, an affiliate-labelled link |
| **Status chip** | The five statuses above, never colour alone (icon plus text) |
| **Fact row** | Value, source link, "checked on" date, amber stale warning (over 30 days) |
| **Badges** | Pehchan-checked and Open to creator stays, visibly different and never merged |
| **Checkpoint row and banner** | Green, amber, red, each with text, not colour alone |
| **Forms** | Text, number with currency, date, file or screenshot upload, repeatable rows (pitches, programmes) |
| **Empty state** | Says what goes here and links to the template or example |
| **AI draft** (phase 3) | "AI draft, edit before sending" label and "Flag this draft" link |

## Screens to design

Landing · first-visit screens 1–4 · 0a list and scoring table (laptop and phone) · 0b area list, stay list and stay
detail · stage 1 panel with step cards · checkpoint · stage 2 Today view (phone first, one-handed log) · stage 3 ·
trip menu dialogs (export, import, share, delete) · offline state · error states.

## Rules from the plan

- Phone first for stage 2; wider comparison tables on a laptop for 0a to 1.
- Large tap targets, strong contrast, every input labelled, nothing that needs a mouse (details in 1.33).
- Show losses plainly; a negative net is never hidden or softened.
- Affiliate links always labelled.

## Acceptance criteria

- [ ] A component library with every state above, in light and dark.
- [ ] Designs for every screen listed, at phone and laptop widths.
- [ ] Owner sign-off recorded before developers build each stage.
