## Why it matters

The plan promises dated, working facts and links. These jobs keep that promise without someone remembering to check.

## Jobs

| Job | Runs | Where | What it does | Admin sees |
|---|---|---|---|---|
| **Link check** | Weekly, Monday 03:00 IST | Inside Strapi, on the CMS server we already run | Opens every outbound link on published trip content: step links, stay booking links and websites, and the source of every destination, visa, climate, festival, permit and emergency entry. Marks `broken` on step links and lists the rest | One email through Resend listing every broken link with where it lives; every result in Strapi under **Trip · Link check** |
| **Advisory check** `/api/cron/advisories` | Daily, 02:00 UTC | Vercel Cron | Asks GOV.UK when each destination country's advice last changed | A changed destination is highlighted on the page with "Advisory changed on [date]" for 14 days, and an email |
| **Exchange rates** `/api/cron/rates` | Daily, 01:00 UTC | Vercel Cron | Checks Frankfurter for each live currency, then refreshes that cached rate | An email only if it fails |
| **Strapi backup** | Daily | On the EC2 server (task 1.06) | Copies the database and uploads off the server | An email if it fails |
| **Cache refresh** | On publish | Strapi webhook (1.05) | Calls `/api/revalidate` | The change live on the page |

Phase 2 adds the weekly creator-count job (2.02).

## Rules

- Each cron route checks `CRON_SECRET` and refuses any other caller.
- The link check is polite: one request at a time per site, a short timeout, a user agent naming the site, `HEAD`
  first and `GET` if refused. A link counts as broken after two failed weekly runs, to avoid false alarms.
- **Free plans only** (owner, 16 Nov 2026). Vercel's free Hobby plan allows each cron job to run at most once a day,
  starting up to 59 minutes late, so the two Vercel jobs are daily. The weekly link check runs inside Strapi.
- **No stored advisory copy.** GOV.UK publishes when each country's advice last changed. Each daily run covers a fixed
  24-hour slot (yesterday's scheduled hour to today's), so a change is emailed exactly once, however late the run
  starts.
- **The link check runs in Strapi** because it must remember each link's result between weeks and write `broken` back
  to step links. Inside Strapi that needs no new API token, no paid storage and no Vercel setting. It changes only the
  `broken` field, so an unpublished edit stays unpublished, and it refreshes the pages through the existing revalidate
  webhook.

## Acceptance criteria

- [ ] All three jobs run on schedule in production, and the two Vercel routes refuse calls without the secret.
  (The refusal is covered by unit tests; production is checked after deploy.)
- [x] A deliberately broken test link appears in the weekly email after two runs. Tested 16 Nov 2026 in a local Strapi
  on an empty database: the link failed once on run 1 (no email) and was broken on run 2, with one email listing only
  that link. It cleared on run 3 after the link was fixed.
- [ ] A changed advisory shows highlighted with its date. The highlight and the 24-hour slot are covered by unit
  tests; it's ticked when a real GOV.UK change shows on the live page.
