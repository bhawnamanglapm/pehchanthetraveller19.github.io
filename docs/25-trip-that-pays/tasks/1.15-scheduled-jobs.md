## Why it matters

The plan promises dated, working facts and links. These jobs keep that promise without someone remembering to check.

## Jobs

| Job | Runs | Where | What it does | Admin sees |
|---|---|---|---|---|
| **Link check** `/api/cron/check-links` | Weekly | Vercel Cron | Opens every outbound link: step links, stay booking links, stay websites, official visa, permit and emergency links. Marks `broken` on step links and lists the rest | One email through Resend listing every broken link with where it lives |
| **Advisory check** `/api/cron/advisories` | Daily | Vercel Cron | Fetches GOV.UK advice for each destination and compares it with the last stored copy | A changed destination is highlighted on the page with "Advisory changed on [date]", and an email |
| **Exchange rates** `/api/cron/rates` | Daily | Vercel Cron | Refreshes the Frankfurter cache | An email only if it fails |
| **Strapi backup** | Daily | On the EC2 server (task 1.06) | Copies the database and uploads off the server | An email if it fails |
| **Cache refresh** | On publish | Strapi webhook (1.05) | Calls `/api/revalidate` | The change live on the page |

Phase 2 adds the weekly creator-count job (2.02).

## Rules

- Each cron route checks `CRON_SECRET` and refuses any other caller.
- The link check is polite: one request at a time per site, a short timeout, a user agent naming the site, `HEAD`
  first and `GET` if refused. A link counts as broken after two failed weekly runs, to avoid false alarms.
- Where the advisory's last copy is stored is a developer choice (a small Strapi collection or Vercel storage); if it
  costs money, ask the owner first.
- Check that the Vercel plan in use allows these cron schedules; if a paid plan is needed, ask the owner first.

## Acceptance criteria

- [ ] All three Vercel jobs run on schedule in production and refuse calls without the secret.
- [ ] A deliberately broken test link appears in the weekly email after two runs.
- [ ] A changed advisory text shows highlighted with its date.
