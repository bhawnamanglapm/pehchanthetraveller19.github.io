## Why it matters

AI drafts save travellers time, but an invented number in a pitch or a missing ad label is a real harm. AI stays off
until it's proven safe for each stage.

## Rules (never change)

- APIs and admin give the facts; AI gives drafts, summaries and matching; a person checks anything public.
- AI never does visa rules, prices, emergency numbers, safety verdicts or scores, and never sends, posts or publishes.
- Numbers come only from the traveller or connected accounts.
- Labels: "AI explanation" (0a), "AI summary of reviews" (0b), "AI draft, edit before sending" (stages 1–3).
- AI output never enters a Strapi field, except a draft the traveller sends with "Flag this draft", which lands in
  `ai-flag` only.

## What to build

| Part | Detail |
|---|---|
| **Route** | `POST /api/ai/draft` with a tool name and the traveller's inputs. Server only; `ANTHROPIC_API_KEY` in environment variables |
| **Checks** | `checks.ts` (copied) runs on every output: blocks invented phone numbers and amounts. Fails → no draft, template shown |
| **Models** | A small model (the radar already uses Claude Haiku 5.5) for logs and captions; a larger one for pitches and edit plans |
| **Cache** | Identical requests return the cached answer |
| **Limits** | Runs only on a tap, never on page load. Daily limit per browser or account from trip-page-settings. When reached, the page says so and the template still works |
| **On/off** | `AI_ENABLED` plus the per-stage switch in trip-page-settings. All off until that stage's evals pass |
| **Flag this draft** | Sends that one draft, the tool name and the traveller's note to `ai-flag` (rate-limited like other forms, 1.16). `ai_draft_flagged` fires |
| **Events** | `ai_draft` (type) |

## Evals (added to the existing eval setup and `eval-score.ts`)

| File | Checks | Pass mark |
|---|---|---|
| `evals/pitch.jsonl` | Drafts never contain a number the traveller didn't give | 100% |
| `evals/caption.jsonl` | Partner posts always carry an ad label | 100% |
| `evals/log-parse.jsonl` | Amount, currency and category read correctly from voice entries | Set when the eval is written |

Every flagged draft that turns out to be a fault becomes a new eval case.

## Admin oversight

Monthly: five random drafts per tool from the eval log (never travellers' trips), and AI cost against the budget.

## Rules from 3.01 (checked 18 Nov 2026)

From the [3.01 findings](../research/3.01-findings.md), item 7:
- **Prices (US$ per million tokens, input / output):**
  - Haiku 5.5: 0.10 / 0.50 (prompts up to 100,000 tokens);
  - Sonnet 5.5: 2 / 10;
  - Opus 5.5: 4 / 20.
- **Example draft** (3,000 input + 1,500 output tokens): about ₹0.10 on Haiku and ₹1.96 on Sonnet.
- **AI stays off until the owner sets a monthly cap.** The daily limit and the cache keep spending under it.
- Run evals through the Batch API (half price).

## Acceptance criteria

- [ ] Evals pass at their marks before any stage is switched on.
- [ ] A draft with an invented amount is blocked in a test.
- [ ] The daily limit and the cache work in tests.
- [ ] A flagged draft lands in `ai-flag` with nothing else from the trip.
