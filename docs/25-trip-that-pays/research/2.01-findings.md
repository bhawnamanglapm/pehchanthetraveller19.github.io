## 1. Travelpayouts (Aviasales) Data API

**Answer**
- Access is with the personal Travelpayouts token, after joining Travelpayouts and connecting the Aviasales programme.
  No fee is mentioned. The token goes in the `X-Access-Token` header (official API docs).
- The data is **not live**. It comes from Aviasales' cache of its users' searches. For example, the "latest prices"
  call returns "prices found by our users during the most recent 48 hours". Each price has an `expires_at` field, and
  "It is not recommended to use expired prices" (official API docs).
- Travelpayouts recommends using the data "to generate static pages" and caching on our side (official API docs).
- The live Flights Search API is only for projects with **50,000+ monthly users** and has strict rules (searches
  started by the user, no automatic collection). It is not for us (help centre, via search).
- Bidding on Aviasales or Hotellook brand names in search ads is banned (official blog, rules post, 2016).

**Not confirmed:** the help centre pages on access rules and rate limits block automatic reading, so their exact text
was not read. Their search summaries conflict (2 to 7 days' storage, 24-hour cache advice). **Check the rate limit in
the Travelpayouts dashboard** before 2.03 goes live.

**Verdict: Build, limited (₹0).** Cache on the server for a few hours at most. Drop any price past its `expires_at`.
Label every price as "found by Aviasales users on [date]; may have changed".

**Sources**
- [Travelpayouts API docs](https://travelpayouts.github.io/slate/) (official)
- [Requirements for Aviasales Data API access](https://support.travelpayouts.com/hc/en-us/articles/203956083-Requirements-for-Aviasales-data-API-access) (official; read through search only)

## 5. Google Trends API

**Answer:** it is in **alpha**. Developers apply through a form, and Google says it is "prioritizing developers that
know what they want to do, that can start doing it soon, and that are willing to provide feedback". The data covers
the last 5 years, daily to yearly, by country and sub-region. No terms of use, pricing or rate limits are published.

**Verdict: Don't build now.** Applying is free and optional. Don't plan any feature around it until it's generally
available.

**Sources**
- [Google Trends API alpha](https://developers.google.com/search/apis/trends) (official)
- [Announcement, July 2025](https://developers.google.com/search/blog/2025/07/trends-api) (official)

## 6. YouTube Data API v3

**Answer**
- **Free daily quota:** "100 `search.list` calls, 100 `videos.insert` calls, and 10,000 units per day combined for
  all other endpoints". `search.list` costs 1 call from its own 100. `channels.list`, `videos.list` and
  `playlistItems.list` cost 1 unit each.
- **More quota:** apply through a form, which needs an API Compliance Audit (Developer Policies III.D.3).
- **The 30-day rule:** data not authorised by the channel owner may be stored "not longer than 30 calendar days".
  After that it must be refreshed or deleted (III.E.4.d).
- **Statistics:**
  - View counts are exempt from the 30-day limit only when they come with the owner's authorisation (III.E.4.b).
  - A channel's subscriber count "must not" be stored for more than 30 days without the channel owner's authorisation.
  - 2.02 has no authorisation, so the 30-day rule applies to **every** count it stores.

**Verdict: Build (₹0).** A free Google Cloud project and API key are enough.
- The 100 searches a day limit the number of places per run, so spread places over the week as 2.02 already plans.
- The weekly refresh keeps every count well inside 30 days.
- Delete anything older than 30 days.

**Sources**
- [Developer Policies](https://developers.google.com/youtube/terms/developer-policies) (official; no updated date shown)
- [Getting started: quota](https://developers.google.com/youtube/v3/getting-started) (official)
- [Quota costs](https://developers.google.com/youtube/v3/determine_quota_cost) (official)

## 8. Booking.com Demand API

**Answer:** the partner must be a Booking.com **Managed Affiliate Partner**. Partner Centre access is "provided by your
Booking.com Account Manager after signing the agreed contract". Then the partner makes an API key and an
`X-Affiliate-Id` in Partner Centre. There's no self-service sign-up.

**Verdict: Don't build now.** Revisit when traffic is large enough for Booking.com to offer an account manager.

**Source:** [Demand API prerequisites](https://developers.booking.com/demand/docs/getting-started/prerequisites) (official)
